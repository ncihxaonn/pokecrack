## 结论：当前小岛方案没有达到参考一致性

Kage 是地面视角的、贯穿整页的空间行进。镜头从植被前走向山门，左右错位取景，穿过前景，最后抬升到主殿。当前实现把三栋建筑缩成了一个陈列小岛，使用俯视环绕与固定信息栏，改变了参考的空间尺度、运动方向、图层关系和叙事结构。复用 Three.js、屋顶函数和阻尼数值，并不等于还原其动效。

| 当前实现 | 原版需要保留的行为 | 对观看感受的影响 |
| --- | --- | --- |
| 俯视环绕一个完整小岛 | 地面低机位沿路径推进、左右移位、后段升高 | 原版让观众进入空间，当前像观看模型 |
| 所有建筑一直完整装在画面里 | 近景草木、巨字、门柱、屋檐占据甚至超出画面 | 遮挡和大小变化建立强烈纵深 |
| 固定左栏切换三组内容 | 各章节正文滚动进出，画布保持贯穿整页 | 内容参与行进，而不是附在模型旁边 |
| 普通标题，没有空间巨字 | 每个巨字是独立 WebGL 平面，被草遮住，逐字升起再溶解 | 品牌文字成为场景中的物体 |
| 少量云和漂浮几何体 | 多层草木、雾、落叶、灯光、涟漪与颗粒 | 连续的环境运动让空间具有气氛 |
| 未使用原版图片/前景资产 | 摄影感图片、透明前景和布料形变 | 原版细节感并非单靠几何模型获得 |

## 实际镜头路线

完整浏览了首屏、山门、花园图片、手艺章节、尾声、页脚，并在花园图片上横向划过指针。1440×900 视口、字体加载完成后的 DOM 锚点约为 0、898、1850、2920、3936、4476px；该数值随布局变化，不能写成固定整页百分比。

以下百分比是相机路径进度，源自原始六个机位（源码 4034–4040）：

| 路径位置 | 镜头 | 呈现内容 |
| --- | --- | --- |
| 0% | 正面低机位，望向远处主殿 | 前景草木、巨大 KAGE、山门、红月、首屏文案 |
| 20% | 向左移、降低、广角扩大 | 山门介绍和数字；近景横向视差明显 |
| 40% | 明显前推，经过最前方植被 | 左侧大图、右侧两张图，背景仍是同一处寺院 |
| 60% | 转到右侧低机位 | 门柱和屋檐变大，章节介绍板经过前方 |
| 80% | 穿过山门的深度，抬升镜头 | 靠近主殿，竖排尾声标题与 CTA |

相机位置 z 从 13.6 经 11.6、2.2、-3.4 推进到 -16、-20；鸟居位于 z=-8.6，主殿约 z=-44。相机没有围绕小岛转一圈。位置和观察目标分别用 Catmull-Rom 曲线，FOV 随机位从 36°、48°、40°、46°、42°到 46°变化（4034–4083）。

## 动效是几套系统协作

1. **开场镜头**：约 2.4 秒的推进，同时从更宽视角收进正式机位；画面约 700ms 淡入。大字逐字从草后升起。依据：4073–4075、4631–4639、4674、4688–4691。
2. **原生滚动驱动镜头**：页面不劫持 wheel/touch；按每章中心对齐视口中心计算锚点。相机以 `1-exp(-5.2×dt)` 平滑跟随；鼠标只引入轻微视差，不能自由旋转场景。依据：4088–4103、4077–4080、4669–4687。
3. **首屏分段退出**：开始滚动后的 0–58vh，预览小窗先模糊溶解，滚动提示和四个编号逐个消失，最后是日文竖排；不是整个首屏一起滑走。部分元素下移 15px，小窗模糊最多 10px。依据：4290–4321。
4. **空间巨字**：四个独立 WebGL 字面位于 z=3，与草木有遮挡关系；在靠近的第一段路径中逐步溶解。不是置顶的普通 HTML 字。依据：3018–3067、4631–4639。
5. **两类前景**：WebGL 草木具有真实 z 深度，接近镜头时逐层溶解；各章还有固定在视口底部的透明图片组合。新组合逐个升起，旧组合下沉、缩小、模糊后退出。依据：2959–3004、4230–4268、4642–4647。
6. **图片布料**：实际桌面页面的三张 `.card-fr` 均带 `on-cloth`。成功启用后，它们使用独立 WebGL2 画布中的摄影图片，不再使用下层的实时场景卡片渲染。96×96 网格、顶部固定，指针局部托起布面、风力造成起伏，悬停时边缘增亮。粗指针设备跳过布料。依据：3499–3504、3646–3661、3845–3870、4537–4539。
7. **正文编排**：标题按词错开 72ms；同组内容错开 85ms，进入视口时出现。不是随着章节切换，整块替换固定位置的标题。依据：4146–4189。
8. **环境动效**：雾横移、枫叶落下、灯笼闪烁、月光呼吸、水面涟漪、鼠标后面的冷色光尘。悬停章节时灯光加强，场景机位仍由滚动控制。依据：3174–3381、4396–4404、4597–4628。

## 对宝可梦版本的约束

下一次实现应先用用户给的完整 Kage 页面与必需的本地图片资产建立原版基准，确认镜头、遮挡、巨字、分段退出和图片交互一致，再替换成宝可梦建筑、植被、材质、文字和真实数据。参考中的大场景尺度、低机位、前进行进、近景遮挡应该保持。

当前小岛方案的细节润色不能解决参考一致性；需要重做场景与页面的空间组织。宝可梦视觉并不要求照搬原版黑红色，但换色或替换建筑也不能牺牲这些运动关系。

验收应该看完整滚动过程，至少覆盖开场、第一段退出、两段近景穿越、图片互动、最终抬升，以及反向滚动，而不只检查三个终点截图或确认 WebGL 正常运行。
